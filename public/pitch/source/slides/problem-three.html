The problem · merchant side

Three ways the merchant loses

01

Invisible

Agent reach is rented from two chat apps. Every other agent gets turned away.

Even top agents finish only about 70% of WebArena web tasks.

02

Unpaid

Checkout needs a human: login, saved card, 3DS. An agent can’t pay on its own.

Cross-border card payouts add fees and days of delay.

03

Exposed

Product text is untrusted. One poisoned listing can change who gets paid.

Prompt injection is #1 on the OWASP Top 10 for LLM apps.

Three concrete pains for the merchant. One: invisible. Agent reach is rented from two chat apps, and even the best agents only finish about 70% of web tasks on the WebArena benchmark, because the web is built for humans. Two: unpaid. Checkout assumes a human with a login, a saved card and 3DS. An agent can’t set up a billing relationship by itself, and cross-border card payouts cost fees and days. Three: exposed. Listing text is untrusted input. A poisoned product description can tell a buying agent to pay someone else, and the merchant’s brand takes the hit.
