Here’s exactly what happens. Once: the agent wallet signs in to AP4M and opens a payment channel with an RLUSD cap and the merchant ID. Then per purchase: the buyer approves the locked quote in chat, we redeem a cumulative voucher, which is what’s already redeemed plus this price, and we get back a claim ID and an XRPL EVM transaction as the receipt. We added three guardrails on top: we check the cap before signing anything and tell the buyer what’s left; every order is idempotent, so a network retry returns the same receipt instead of paying twice; and we read the channel state on-chain before every redeem, so a closed channel can’t settle.
