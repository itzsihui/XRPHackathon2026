How it works

From catalog to settled RLUSD

Merchant

Chat, CSV or URL becomes a catalog

Registry

llms.txt and a search API, no scraping

Any agent

Discovers stores and picks a SKU

HTTP 402

x402 challenge with a locked quote

XRPL

Settles in seconds. Merchant gets RLUSD

Locked quote

{ storeSlug, skuId, price, payTo }

The pay path only sees these four fields. Product text can’t change who gets paid or how much.

Verified sellers

XLS-70 credential + XLS-40 DID

Any agent can check a seller on any XRPL node, without trusting Borneo.

Under the hood: the merchant’s catalog goes into an open registry, exposed as llms.txt, registry.json and a search API. Any HTTP agent discovers a store and picks a SKU. It calls buy and gets an HTTP 402 Payment Required with a locked quote. It pays, and it settles on the XRP Ledger in seconds in RLUSD. Two safety pieces: the locked quote means the payment path only ever sees store, SKU, price and payTo, so a poisoned product description can’t redirect money. This is inspired by DeepMind’s CaMeL design. And sellers carry an on-ledger verified-seller credential plus a DID that agents can check themselves.
