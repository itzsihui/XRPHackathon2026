Mastercard · AP4M deep dive

Give agents a budget, not a card number

Capped

The buyer’s agent opens one payment channel with a hard RLUSD cap. It can never spend past it.

Accountable

The agent signs in with a registered wallet and pays a known merchant ID. Every spend is attributable.

Instant

Each purchase redeems a voucher in RLUSD on XRPL EVM. No per-purchase card authorization round trip.

For Borneo merchants: Mastercard-backed agent payments, zero extra integration.

Same locked quote as every other rail. The merchant doesn’t change a thing.

Mastercard · how we built it

One purchase on the AP4M rail

1 · once

Sign in

Agent wallet gets an AP4M session

2 · once

Open channel

RLUSD cap + merchant ID

3 · per buy

Authorize

Buyer approves the locked quote in chat

4 · per buy

Redeem

Voucher for redeemed + price

5 · per buy

Receipt

Claim ID + XRPL EVM tx link

Cap check first

Over-cap buys are refused before anything is signed, with the remaining balance shown.

No double pay

Each order is idempotent: a retry returns the same receipt instead of redeeming twice.

Open channels only

Channel state is read on-chain before every redeem. Closed or expired means no settle.
